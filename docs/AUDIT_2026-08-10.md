# Hexta — Full End-to-End Audit (2026-08-10)

Scope: every backend endpoint, auth flow (login → logout), frontend page/link,
search/RBAC pipeline, ingestion batch, infrastructure/deploy, tests and the
evaluation benchmark. Verified by reading the code and running the suite.

Status of the repo when audited:
- Backend: `157 passed` (pytest, unit + DB integration).
- Frontend: `next build` succeeds; 4 ESLint unused-var warnings in `app/page.tsx`.
- Running code is broadly sound: RBAC is enforced in the SQL WHERE clause,
  queries are parameterized (no SQL injection), the search path contains no LLM,
  and ingestion stays out of the request path.

Everything below is a defect or a gap. Each item has a file reference, a
severity, and a proposed fix. See the Correction Plan at the end for the
recommended order of work.

## 1. Auth / Login / Logout

### A1 [HIGH] Login gate missing on the main chat page
`frontend/app/page.tsx:22,67,190` — `LoginForm`, `authChecked`, `handleLoginSuccess`
are dead code (confirmed by ESLint warnings). A logged-out user lands on the chat
UI with no login prompt; `handleSearch` silently returns when `getToken()` is null
(`page.tsx:116-120`). The login form only appears via the Admin/Analytics/Uploads/
Settings pages.
Fix: render `{!token && <LoginForm onSuccess={...}/>}` on the home page (as the
other pages do), and remove the dead imports/handlers.

### A2 [HIGH] JWT has no `email` claim, but the frontend reads one
`backend/app/auth/jwt_handler.py:31-38` (payload has only `sub/role/department/
allowed_departments/iat/exp`); `backend/app/api/v1/auth.py:89` returns
`email=payload.get("email")` → always `None`; `frontend/lib/auth.ts:46`
(`UserSession.email` always empty); `frontend/components/ui/sidebar.tsx:50-57`
decodes `payload.email` → always shows fallback "user@hexa.local" and wrong
initials (`sidebar.tsx:40-48` reads `payload.email || payload.sub`).
Fix: add `"email": ...` to the token payload in `create_token` (callers already
have the row), or stop claiming email on the frontend and derive it from a
`GET /auth/me` endpoint backed by the DB.

### A3 [HIGH] No logout endpoint / token revocation
`backend/app/api/v1/auth.py` has `/login` and `/verify` only. Logout is purely
client-side (`clearToken()`), so a stolen JWT stays valid for the full
`jwt_expiry_minutes = 480` (8h). There is no denylist and no refresh flow.
Fix: add a `POST /auth/logout` that records the `jti`/`sub`+`exp` into a small
`token_blacklist` table, checked in `get_current_user`; or reduce token lifetime
and add a refresh token. Logout should also be audit-logged.

### A4 [MEDIUM] No rate limiting or lockout on login
`backend/app/api/v1/auth.py:42-71` — unlimited attempts; brute-forceable, and no
failed-login audit trail (CLAUDE.md rule 8 only covers queries; logins are
untracked).
Fix: per-IP + per-email throttling (e.g. `slowapi`/in-Postgres counter) and write
login success/failure events to a new `auth_events` table.

### A5 [MEDIUM] `/auth/verify` ignores user active status
`backend/app/api/v1/auth.py:74-90` — only checks signature/expiry, not
`users.is_active`. A deactivated user's existing token still "verifies" until
expiry (search itself is safe because `get_current_user` does a live DB check).
Fix: have `/auth/verify` look the user up in the DB (same query as
`get_current_user`) and return `valid: false` when inactive.

### A6 [LOW] No session sliding / fixed 8h expiry
Acceptable for the design, but documented so it is a conscious choice. Revisit
if tokens outlive user deactivation windows (see A3/A5).

## 2. API Endpoints

### B1 [HIGH] Knowledge-gap feature is wired to a dead writer
`backend/app/knowledge_gap/gap_detector.py:13` `detect_and_log` has **zero
callers** (grep-verified). `backend/app/api/v1/analytics.py:15-31` reads
`knowledge_gaps`, so the Analytics "Knowledge Gaps" panel can never show data.
Fix: call `detect_and_log(query, intent, confidence)` from
`backend/app/api/v1/search.py` on the `no_answer` and low-confidence outcomes
(both the early-return path at line 80 and the validation-fallback at line 154).

### B2 [HIGH] Frontend/backend upload contract mismatch
- `frontend/app/uploads/page.tsx:24` advertises `.doc` and `MAX_MB = 50`
  (`page.tsx:31`), but `backend/app/documents/validation.py:14` allows only
  `{pdf,txt,docx,html,md}` and `backend/app/config.py:63` caps uploads at 20 MB.
  `.doc` and 20–50 MB files pass the frontend check then fail 400/413 on the API.
Fix: align one side (drop `.doc`, set `MAX_MB = 20`) and surface backend
validation errors verbatim.

### B3 [MEDIUM] Upload buffers the whole file despite the docstring
`backend/app/api/v1/documents.py:44-53,67` accumulates `content += chunk`, and
extension/size validation only happens after full buffering (claimed "never
buffers the whole file", line 32).
Fix: validate extension first, stream to a temp file while enforcing the size
limit, then rename into `storage/pending/`.

### B4 [MEDIUM] `bm25_limit` / `vector_limit` config are dead
`backend/app/search/hybrid_orchestrator.py:53-54` accepts both but never uses
them; the SQL caps only by `max_results=100`. `config.py:66-67` values are
ignored.
Fix: either implement per-signal candidate limits or remove the settings; if
removing, update `.env`/`.env.example`.

### B5 [LOW] Unbounded `limit` params
`documents.py:80`, `analytics.py:17,92` — `limit: int` with no clamp; negative
values are passed straight into `LIMIT %s`.
Fix: clamp to `[1, 500]` via a `Query(ge=1, le=500)` annotation.

### B6 [LOW] Search query length not bounded server-side
`backend/app/api/v1/search.py:35-36` — `query: str` has no `min/max_length`
(frontend limits to 500 chars, but the API is public). Huge/malformed queries
cost embedding + SQL work.
Fix: `query: str = Field(min_length=1, max_length=500)`.

### B7 [LOW] Feedback accepts arbitrary `response_id`
`backend/app/api/v1/feedback.py:34-43` — any string is stored; nothing ties it to
a real response (spam/garbage data).
Fix: verify the response_id exists in `audit_log` before insert (or soft-accept
and flag).

### B8 [LOW] Search 500 on RBAC/approval validation failure
`backend/app/api/v1/search.py:163-166` returns `500` when `validate_package`
rejects for non-confidence reasons. A 500 implies server fault; a caller-triggered
condition should be a 403/204 or an empty safe response.
Fix: return 403 when the cause is RBAC, otherwise an empty `no_answer` package
and log the anomaly.

### B9 [LOW] Admin surface is minimal
`backend/app/api/v1/admin.py` — only `GET /users` and `PATCH /users/{id}`
(is_active toggle). No user create/role change/password reset, and admin actions
are not audit-logged.
Fix: add audit rows for admin mutations (`audit_log`-style `admin_actions`
table) as the priority; user-creation/password-reset as a follow-up.

## 5. Security

### S1 [MEDIUM] CORS `*` + credentials with no production guard
`backend/app/main.py:102-113` — when `cors_origins == "*"` the middleware is set
to `allow_origins=["*"]` **with** `allow_credentials=True`. Nothing enforces the
"permissive in dev only" comment; a production box with `HEXA_CORS_ORIGINS`
unset ships `*`.
Fix: fail-fast in `config.py` when `environment != "development"` and
`cors_origins == "*"` (mirror the JWT-secret guard).

### S2 [MEDIUM] No security headers / no CSP on the static frontend
`frontend/nginx.conf` (and `shared-host-infra-scaffold/.../hexa-assistant.conf`)
set no `Content-Security-Policy`, `X-Frame-Options`, `Referrer-Policy`,
`Strict-Transport-Security`. Combined with JWT-in-localStorage, an XSS would leak
tokens silently.
Fix: add security headers; at minimum CSP, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: no-referrer`.

### S3 [MEDIUM] Backend bound to all interfaces; no TLS
`shared-host-infra-scaffold/infra/systemd/hexa-backend.socket:10` binds
`0.0.0.0:18001`; root `docker-compose.yml:19-20` publishes `18001:8001` with no
loopback prefix; `443` is published in the shared compose but nothing listens on
it (no TLS anywhere).
Fix: bind socket to `127.0.0.1:18001` (nginx proxies host-local traffic), keep
Postgres on `127.0.0.1:15432` (already correct), and terminate TLS at nginx.

### S4 [LOW] Weak bundled dev credentials
`shared-host-infra-scaffold/infra/shared/.env` uses `adminpass`; `backend/.env`
uses the default JWT secret. Both are gitignored (verified), but rotate before
real deployment (config already hard-fails on the default secret outside dev).

### S5 [LOW] Raw audit-logged queries are unredacted
`audit_log.query` stores the raw user text (which may contain PII). Note for
compliance review; consider a `query_normalized` field and retention policy.

## 6. Document Ingestion Batch

### I1 [HIGH] `process_file` has no per-file isolation — one failure kills the batch
`backend/app/documents/ingest_batch.py:49-103` — only text extraction is
try/except'd. A DB error in `index_document` (e.g. embeddings-length mismatch,
constraint violation) propagates and aborts `main()`'s loop, leaving the rest of
the queue unprocessed.
Fix: wrap the body of `process_file` in try/except, log the failure, and return
`False` (so `main()` continues and reports failed count).

### I2 [HIGH] PDF tables are never preserved
`backend/app/documents/chunking/structural_chunker.py:89,104,200-216` —
`_chunk_section` splits body by `\n`, so `_is_table_block` (requires ≥2 lines)
never fires on the PDF path; the documented "tables kept as single chunks"
guarantee is false. Tables are shredded into per-line chunks.
Fix: detect table blocks on line-window/whitespace patterns instead of
`len(lines) < 2`, or run a table-aware pass on the PDF path.

### I3 [MEDIUM] OCR is orphaned — scanned PDFs silently fail forever
`backend/app/documents/ocr.py` has no callers; `text_extraction._extract_pdf`
has no OCR fallback. A scanned PDF yields no chunks → `process_file` returns
`False` → file stays in `storage/pending/` and is re-attempted on every run.
Fix: call `ocr_pdf` when extracted text is empty, and quarantine permanently
failing files (dead-letter dir + error artifact) instead of retrying forever.

### I4 [MEDIUM] Ingestion entity extraction uses naive substring matching
`backend/app/documents/entity_extraction.py:38` — `term_lower in lowered`
matches "va"/"id" inside unrelated words, corrupting metadata/faceting. Query-time
extraction uses word-boundary regexes (`query_processing/entity_extraction.py:32`).
Fix: reuse the word-boundary matching logic from the query path.

### I5 [MEDIUM] Embedding failure is silently swallowed
`backend/app/documents/ingest_batch.py:77-84` — on embedding error, chunks are
indexed with `embedding = NULL`, the file is moved to processed, and nothing
flags it. Those chunks are permanently invisible to vector search.
Fix: fail the file (or mark `needs_reindex`) instead of silently indexing without
embeddings.

### I6 [MEDIUM] Chunk size derives from a response-display setting
`backend/app/documents/ingest_batch.py:69` — `StructuralChunker(max_tokens=
settings.max_excerpt_chars // 2)`. Raising `max_excerpt_chars` silently doubles
ingested chunk size. Add a dedicated `chunk_max_tokens` setting.

### I7 [MEDIUM] `_move_to_processed` crashes on Windows when destination exists
`backend/app/documents/ingest_batch.py:37-46` — only `FileNotFoundError` handled;
`FileExistsError` (two files with same basename / re-run after partial crash)
kills the batch. (POSIX silently overwrites — inconsistent behavior.)
Fix: handle `FileExistsError` (e.g. unique suffix or overwrite).

### I8 [LOW] Dead/NER modules with stale APIs
`query_processing/ner/gliner_extractor.py` (never imported; uses removed
`gliner.load`/`result.get("entities")` API → latent `AttributeError`),
`spacy_pipeline.py`, `chunking/{recursive,checklist,table}_chunker.py` (never
imported; yield `str`, not `Chunk`), `audit/models.py`. Remove or fix them.

### I9 [LOW] Orphan `documents` rows on duplicate re-ingest
`backend/app/documents/indexing.py:48-56,81` — a `documents` row is inserted even
when every chunk is a duplicate (`ON CONFLICT (content_hash) DO NOTHING`), leaving
empty documents rows.
Fix: insert the document only if ≥1 chunk is actually new, or clean up empty docs
afterwards.

### I10 [LOW] `import sys` unused (`ingest_batch.py:20`); `min_tokens` dead field
(`structural_chunker.py:31`).

## 7. Infrastructure / Deploy

### X1 [HIGH] Shared nginx serves a path never mounted into the container
`shared-host-infra-scaffold/infra/shared/nginx/conf.d/hexa-assistant.conf:15`
roots at `/opt/projects/hexa/frontend/out`, but `infra/shared/docker-compose.yml:69-70`
mounts only `./nginx/conf.d` — every static frontend request 404s behind the
production proxy.
Fix: mount the frontend export into the container, e.g.
`/opt/projects/hexa/frontend/out:/srv/hexa/out:ro` and point `root` at `/srv/hexa/out`.

### X2 [HIGH] Deploy workflow self-breaks and never activates the app
`.github/workflows/deploy.yml:165` — `sudo systemctl restart nginx` targets the
**system** nginx which the README explicitly forbids installing (Docker-only); with
`set -euo pipefail` this aborts the deploy. The workflow also never installs the
systemd units/socket, never runs `migrate_db.sh`, and never reloads the backend —
newly synced backend code isn't served until the next idle cycle.
Fix: replace the restart with `docker compose -f infra/shared/docker-compose.yml
up -d` (or `nginx -s reload` in the container), and add steps to install
`shared-host-infra-scaffold/infra/systemd/*`, enable `hexa-backend.socket`, run
`migrate_db.sh`, and `systemctl restart hexa-backend.socket` (graceful: triggers
new socket, service starts on next connection).

### X3 [HIGH] Ingestion/migrate scripts resolve the backend to the wrong path
`shared-host-infra-scaffold/infra/scripts/run_ingestion.sh:18` (and
`migrate_db.sh:11`) — `"${SCRIPT_DIR}/../../.."` is correct only in the repo
layout. Installed to `/opt/projects/hexa/infra/scripts/` (per README and
`hexa-backend-idle.service:5`), it resolves to `/opt/projects/backend`.
Fix: `BACKEND_DIR="${HEXA_BACKEND_DIR:-$(cd "${SCRIPT_DIR}/.." && pwd)/backend}"`
(or hard-set the install path) and have the deploy set `HEXA_BACKEND_DIR`.

### X4 [MEDIUM] `migrate_db.sh` cannot authenticate as the superuser
`infra/scripts/migrate_db.sh:23-29,42-43` sources only `backend/.env` (no
`POSTGRES_SUPERUSER_PASSWORD`); the value lives in `infra/shared/.env`.
Fix: source `infra/shared/.env` too and pass the password via `PGPASSWORD`.

### X5 [MEDIUM] Idle-stop measures idle from service start, not last activity
`infra/scripts/idle_stop_watcher.sh:34-37` uses `ActiveEnterTimestamp` (changes
only on start/restart). A service that started at t=0 and served a request at
t=9 min is killed at t=10 — false idle-stop / cold-start latency for bursty use.
Fix: record a "last active" marker (e.g. `systemd-notify WATCHDOG=...` heartbeat
from the app, or touch a timestamp file in the app on each request) and compare
against that.

### X6 [MEDIUM] systemd unit requires a `.env` the deploy never provisions
`infra/systemd/hexa-backend.service:9` `EnvironmentFile=.../.env` is fatal if
missing; the deploy artifact excludes `.env` (gitignored) and nothing creates it.
Fix: have the deploy create `.env` from `.env.example` + secrets on first boot.

### X7 [MEDIUM] Root compose has no memory caps (rule 10)
`docker-compose.yml:13-54` — backend and frontend run uncapped, unlike the shared
compose/systemd paths.
Fix: add `deploy.resources.limits.memory` (backend 200m, frontend 30m).

### X8 [MEDIUM] `embedding_cache_dir` mismatch (see C1) — same root cause.
### X9 [LOW] Port 18001 collision between root compose and the systemd socket
(`docker-compose.yml:19-20` vs `hexa-backend.socket:10`). Document mutual
exclusion or use different ports.
### X10 [LOW] Read-only model volume breaks first-time model download
(`docker-compose.yml:36` `:ro`; fastembed must write on first use) — pre-stage or
make writable.
### X11 [LOW] Raw SQL interpolation of app password in
`infra/shared/postgres/init/02_set_app_password.sh:11` — a `'` in the password
breaks it; use `psql -v` binding.
### X12 [LOW] Unpinned action `easingthemes/ssh-deploy@main` (`deploy.yml:130,140`).
### X13 [LOW] `HEXA_RERANK_ENABLED=true` in `backend/.env` vs `false` in
`.env.example` (E1) — decide and document; with rerank on, verify the reranker
model is actually staged at the anchored path or the "budget" warning path
silently no-ops.

## 8. Tests & Evaluation

### T1 [HIGH] The rule-7 benchmark gate measures nothing about ranking
`evaluation/run_benchmark.py:27-30` imports `precision_at_k`, `recall_at_k`,
`mean_reciprocal_rank`, `ndcg_at_k`, `hit_rate` but **never calls them**. It only
reports sub-question/intent/entity accuracy and latency. CLAUDE.md rule 7 names
this as the gate for ranking-weight changes, but it would not detect a ranking
regression.
Fix: call the metrics against the retrieved candidates for each dataset item and
include `precision@k/recall@k/MRR/nDCG/hit_rate` in the summary + report.

### T2 [MEDIUM] Intent accuracy can never reach 1.0
`evaluation/run_benchmark.py:67-71` requires *every* sub-query intent to equal the
single `expected_intent`; multi-intent items (id=2, id=10) can never pass
(intent_accuracy stuck at ~0.5833 in all committed reports).
Fix: score intent as "matched if any sub-query intent matches" (or per-sub-query
expectations), and record both.

### T3 [HIGH] `httpx` missing from requirements — fresh CI installs fail
`backend/requirements.txt` / `requirements-dev.txt` omit `httpx`; seven test files
use `fastapi.testclient`, whose import chain needs `httpx`. Local `.venv` has it
installed ad hoc, masking the break in CI (`ci.yml:44-45` only installs
`requirements.txt` + pytest).
Fix: add `httpx` (and `requests`, needed by `backend/evaluation/search_benchmark.py:20`)
to `requirements-dev.txt`.

### T4 [MEDIUM] Search success path is untested
`backend/tests/unit/test_backend_skeleton.py:189-200` sends `"Bearer test"` (an
invalid token) and asserts `in (200, 401)` — it only ever returns 401, so the
200 package-build→validate→audit path never runs. (The `search` happy path should
be covered with a mocked `acquire`/embeddings, like `test_search_fallback`.)
### T5 [LOW] `test_rbac_prefilter.py` is labeled "integration" but is DB-free;
`test_search_rbac.py:51-55` `test_no_user_denies_all` body is empty (`pass`).
### T6 [MEDIUM] Eval dataset is dead/misnamed and small
`evaluation/datasets/eval_20_questions.jsonl` is referenced by nothing (it is a
JSON array, not JSONL); `load_dataset()` returns a hardcoded 12-item `DATASET`.
### T7 [MEDIUM] Retrieval benchmark silently shrinks the denominator
`evaluation/retrieval_benchmark.py:258` — 6/20 gold phrases are absent from the
seeded KB, so MRR/recall are computed over 14 queries without reporting it
(`gold_not_found_ids` in the latest report).
### T8 [LOW] Inconsistent p95 definitions between
`evaluation/metrics/latency_benchmark.py:27-28` (np.percentile) and
`evaluation/retrieval_benchmark.py:219-225` (nearest-rank).
### T9 [LOW] `retrieval_benchmark.py:134-153` duplicates the hybrid SQL instead of
calling `search_knowledge_base` (drift risk); `:265` uses a `" || "`→`" && "`
string hack; `run_benchmark.py:43` `total_latency_ms` unused duplicate key.
### T10 [LOW] No pytest config / relies on CWD for imports; several test files hack
`sys.path` individually. Add `pytest.ini`/`pyproject.toml` with `testpaths`.

## 9. Correction Plan (recommended order)

### Phase 1 — Fix broken features (user-visible, no architecture change)
1. **A1** — Add the login gate to the home page; remove dead code.
2. **B1** — Wire `detect_and_log` into `search.py` (knowledge gaps work).
3. **B2** — Align upload contract (extension + 20 MB limit) across FE/BE.
4. **A2** — Add `email` to the JWT (fixes sidebar/settings/getSession).
5. **D3** — Remove or wire the dead paperclip/mic controls.

### Phase 2 — Security hardening (before any real deployment)
6. **S1** — Fail-fast CORS `*` outside development.
7. **A3/A4/A5** — Logout endpoint + blacklist, login rate limiting, verify checks
   active status; audit login events.
8. **S2/S3** — nginx security headers; bind backend socket to 127.0.0.1; TLS at
   nginx; don't publish 443 unless terminating TLS.
9. **X2/X1/X3/X4/X6** — Repair the deploy pipeline (no `systemctl restart nginx`,
   install systemd units, mount frontend out into shared nginx, fix script path
   resolution, provision `.env`, fix migrate superuser auth).

### Phase 3 — Ingestion reliability
10. **I1** — Per-file try/except in `process_file`.
11. **I3/I5** — OCR fallback + dead-letter quarantine; don't silently index
    without embeddings.
12. **I4/I6/I7/I2** — Word-boundary entity matching, dedicated chunk-size
    setting, `FileExistsError` handling, table preservation.
13. **C1/X8** — Anchor `embedding_cache_dir`.

### Phase 4 — Quality gate that actually gates
14. **T1/T2** — Make `run_benchmark.py` compute and report real retrieval metrics;
    fix intent scoring. Re-run and record new baselines in `evaluation/reports/`.
15. **T3** — Add `httpx`/`requests` to requirements-dev; CI will then pass from a
    clean install.
16. **T4/T5/T6/T7** — Cover the search 200 path; fix empty tests; reconcile the
    eval dataset; report the true denominator.
17. **B4/B5/B6/B7/B8/B9, D2** — Dead config, parameter clamps, feedback
    validation, 403 vs 500, admin audit logging, role-aware sidebar.

### Phase 5 — Housekeeping
18. **D5/D6, C2, I8/I9/I10, T8/T9/T10, X7/X9/X10/X11/X12/X13** — dead code/module
    removal, docs sync (`.env.example`, README deploy steps, `docs/`),
    memory caps in root compose, documented port/toggle decisions.

### Definition of done for this audit
- Every HIGH and MEDIUM item above is resolved or explicitly deferred with a
  tracked ticket.
- `pytest` green from a clean `pip install -r requirements-dev.txt`.
- `npm run lint` and `npm run build` clean.
- `python -m evaluation.run_benchmark` reports real retrieval metrics with a new
  baseline committed under `evaluation/reports/`.
- Deploy workflow can run end-to-end on a fresh EC2 box (systemd socket
  activation + shared nginx serving the frontend).
